# 公共游戏数据

新增材料统一走 [材料导入与核定](../materials.md)，不要重放日期脚本。先核定来源与 verified_fields，再 dry-run，确认后事务发布。查询对应红度用 materials.py query；已核单独机制先查 game/facts.json，不能将机制事实扩大成完整满级认证。

当前可信度字段为 `trust_status`（可信/需要确认）及 `trust_reason`，覆盖武将基础定义、战法正文、战法等级观察、武将实测四维。武将和战法主表另有 `screenshot_verified_fields` JSON 数组，逐字段列出已由游戏截图核实的字段；空数组表示尚无可核实的主表截图字段，不等于实体不存在。截图删除后，这一字段、转写正文、等级观察、来源ID及核定原因仍保留；但不能把某个技能截图当作整名武将所有字段可信，也不能把选卡短摘要当完整战法详情。`trust_status`仍是当前可信度判定，截图标记不是无条件覆盖冲突的免检章。用户图片数据可信仅限明确显示字段；网页、缺来源、无详情及残缺记录需要确认。`verification_status`保留历史，不能因旧值Steam已核而绕过可信度。断敌粮道10级本地一红113.3%与本期演武白板110%均已有用户完整截图：等级观察分别记`advancement_confirmed=1`和`advancement_confirmed=0`，不因不同红度场景反复覆盖主表白板基准。`advancement_hypothesis`仅留给尚未核定的红度推测，断敌旧记录的该字段已清空。披坚、五雷仍按各自证据边界处理。原始网页快照保留但不算可信数据。

本地原图要排除出Git时，按 `docs/materials.md` 为转译文本保存SHA-256锚点和 `IMAGE_TEXT_TRANSCRIPTION_V1` 标记，在来源索引保留 `evidence_id`、`transcription_ref` 与字段级可信信息。标记只提供原图身份和文本关联的校验，不证明转写未被改动，也不替代 `trust_status/trust_reason`。

读取任何技能前先检查 [技能勘误与证据优先级](../../game/rules/技能勘误与证据优先级.md)。数据库是检索入口，不是绝对正确保证；旧来源、摘要与本期直接证据冲突时不得自动采用旧值，应记录冲突并向用户求证。文档级勘误不等于数据库满级正文已修复。

公共库在 `game/game.sqlite3`，只存定义、规则和来源。个人库存不得写进公共库；配将建议放在参考层。

日常任务不需要联网同步。现有网页原始快照和战法观察保存在 `game/sources/`；离线完整重建使用不含账号数据的 `public-baseline.sql`：

```powershell
python scripts/sync_game_data.py --output game/rebuilt.sqlite3
```

默认输出为公共库，若基线与当前库不同则拒绝覆盖，先在独立输出中比较。重建会检查用户仍引用的实体，不能静默移除它们。停用的历史联网采集脚本已清理，当前入口只负责离线重建。

新增或修正公共数据时同时更新公共库、SQL 基线和来源索引，在独立库校验后替换；实体 `entity_id` 保持稳定。通过 `migration-conflicts.json` 可查看两份旧库冲突，主库值被保留，次库证据没有被当作已确认的新值。

库存截图发现公共库缺失的新武将或战法时，也按此流程新增公共定义。只录入图片或用户明确确认的字段，未证实的效果、赛季和其他属性保持未知或“需要确认”；个人拥有状态只进个人库存，不写入公共库。公共实体核准并可从 SQL 基线重建后，再让库存增量按名称匹配其 ID；身份无法确认时先求证，不留下无 ID 的新库存项。

`first_season` 表示首发；`applicable_seasons`、`platform` 表示有证据支持的适用范围。缺少依据时为 null；来源的赛季不等于实体只可用于该赛季。
