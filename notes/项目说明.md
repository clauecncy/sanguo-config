# 项目说明

## 单文件交接入口（2026-09-09）

- `项目复现指南-库存统计与50队配对及演武规则.md`：库存统计、模板匹配和演武流程，内嵌当前库存与50队150行参考快照。
- 快照不自动同步；转录仍需校字。单MD不含数据库、脚本及截图，不等于完整程序交付。
- 当前约定仅本地Git；下方历史自动拉取/推送记录不构成后续远端授权。

## 项目目的

记录《三国：谋定天下》Steam 初始服账号已拥有的武将、战法、阵型规则和配队建议，并维护可计算的 SQLite 基础数据库，作为后续对话的长期资料。获得新武将、战法、面板或版本实时信息后，在同一项目内追加更新。

## 输入和输出文件

- 输入：用户截图、用户明确说明、必要时查询到的当前版本资料。
- 核心库存：`武将战法库存.md`
- 战力规则库：`战力机制资料库.md`，记录缘分、阵型、自带战法和通用战法效果，并标注版本可信度。
- 当前建议：`阵容推荐.md`
- 第三方 S1 梯队参考：`S1强队模板库.md`
- SQLite 数据库：`data/三国谋定天下_Steam_S1.sqlite3`
- 数据库说明与覆盖率：`数据库说明.md`、`data/覆盖率报告.md`
- 同步与验证脚本：`scripts/sync_game_data.py`、`scripts/verify_database.py`
- 业务规则：`notes/业务逻辑.md`
- 变更历史：`notes/变更记录.md`

## 运行方法

日常查看可直接打开 Markdown。需要同步网络数据时，按 `数据库说明.md` 运行 Python 脚本；数据库使用 SQLite，无需安装服务。

## Git 协作规则

- 每次开始实际修改或分析任务前，先检查工作区并执行 `git pull --ff-only origin <当前分支>`，以远端为准确认同一数据基线。
- 每个较大、可独立验证的功能点完成后，执行本地提交并推送到已配置的同名远端分支；仅提交本次涉及的源码、数据和项目记录。
- 遇到未提交本地变更、非快进、冲突或远端分支不一致时，不使用强推、重置或覆盖；先保留变更并按实际冲突处理。
- 项目目录内的常规读取、编辑、测试、本地 Git、拉取与推送均按用户授权直接执行。宿主平台的强制安全审批不由项目规则绕过。

## 系统兼容性

Markdown 文件与操作系统无关，Windows、macOS、Linux 均可阅读；游戏账号当前为 Windows Steam 版初始服。

## 依赖和已知限制

- 同步脚本使用项目运行环境中的 Python 3、标准库和 `lxml`；已有数据库可脱离网络直接查询。
- 当前账号库存不维护武将等级、战法等级、编队与携带者；维护拥有状态与红度，保留50级默认四维估算和有来源的10级满战法详情。
- 游戏平衡调整和赛季规则可能变化；联网资料只作为辅助，若与游戏内截图冲突，以当前账号游戏内显示为准。Steam S1 与移动端历史版本不默认等同。
- 当前库存不含装备、坐骑和完整韬略库存。
- 公开成长值只显示两位小数，等级面板推算可能相差 1 点；速度阈值优先用 Steam 实测面板。
- 暂无可信的 Steam S1 全量韬略推荐来源，数据库保留对应表和缺口状态，避免跨赛季猜填。

- 战法满级实测：data/tactic_level_observations.json保存结构化种子，SQLite表tactic_level_observations仅导入10级效果和来源；不将缺乏等级依据的旧正文当作满级数据。

## 当前库存入口（2026-09-08）

- 当前账号为S2；SQLite文件保留历史S1文件名以兼容旧路径，meta.default_season=s2。
- 唯一库存种子为data/account_inventory.json；离线更新运行scripts/account_inventory.py，校验运行scripts/verify_database.py。
- v_owned_generals列出拥有金将、版本、红度和50级未加点四维；常驻库存筛选availability='常驻'。
- v_owned_tactics列出拥有金/紫战法、红度证据日期和满级详情；未知红度为NULL，不等于0红。
- 全局参考定义不等于账号拥有；紫色武将已从SQLite删除。旧活动和原始网页快照只作历史资料。
