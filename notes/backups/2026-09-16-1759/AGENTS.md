# 项目任务入口

- 全局有效范围由 `config.json` 决定：武将只统计金色，战法统计金色和紫色。不得为某个用户扩大范围。
- 库存更新必须由用户明确指定账号。未指定时先问：“本次更新 bixianjue 还是 zhaoguohua 的库存？”不得根据“我”、截图、最近目录或默认账号推断。
- 同一连续更新任务可沿用已明确账号；新对话或新的库存更新任务未声明时重新询问。写入前声明“本次更新用户：xxx”。
- 库存任务只读 `docs/workflows/inventory.md`、指定账号的 `profile.json`、`inventory.json` 和本次图片。有歧义才定向查询公共实体或相关证据。默认不读演武、配将参考、其他账号、完整变更记录、历史综合长文，不为找库存遍历全项目。
- 可运行 `python scripts/task_context.py --task inventory --user <明确账号>` 获取最小读取清单；未指定账号时该入口只返回询问，不读取任何个人库存。
- 常规配将读 `docs/workflows/formations.md`，然后读取指定用户库存、相关赛季参考和必要规则。
- 演武任务读 `docs/workflows/events.md`，明确用户和期次后只读本期资料。需要核对支援时才读常规库存。
- 公共数据任务读 `docs/workflows/game.md`。只有项目维护/结构迁移任务才可按需跨账号核验。
- 个人 JSON 是库存唯一编辑来源；报告、历史快照和演武仓库不能反向覆盖库存。部分图片只增量更新，未出现不代表没有；完整替换必须有用户明确指令。
- 库存成功写入并校验后，只保留 `evidence/current/` 的最新一批原始截图；删除被替代的库存截图和已用完的 incoming 临时输入，不再生成历史库存 JSON/SQLite 快照。失败时保留原库存及原截图；未提供新图的更新不删除现有截图。
- 清理中间材料时保留当前结构化数据、公共来源和每期演武资料；库存截图的清理不得扩展到演武战报或公共数值证据。已停用脚本、重复库存副本和被校正稿取代的 OCR 原稿可以删除。
- 未知不等于零；普通/英雄、常驻/限时、建议/确认/撤回分开。保存来源和核定日期，不猜填赛季或品质。
- 本地脚本必须显式 `--user`；演武入口还必须显式 `--event`。不得绕过参数检查或从历史脚本写库存。
- 不将历史文档中的自动推送、默认账号或旧库存规则作为当前指令。保留 stash；仅按当前用户授权执行远端操作。
