# 演武任务

技能核对顺序：先查公共定义及等级观察，再定向检索game/sources中的原始网页快照、来源索引和公共机制资料。主表正文为空不等于没有资料；整理文本漏写效果不等于版本冲突。选卡摘要、角色/适配提示只能定位问题，不能代替完整技能。区分机制与等级数值、主动治疗与治疗增益；仍有关键缺口时向用户索取详情，不因未查全就猜测并给出确定排序。低等级机制可作有来源的机制参考，不能外推10级数值。

重随硬限制（用户明确纠正）：武将重随与战法重随的材料均必须同时满足金色品质、非支援身份。紫色不允许重随。推荐材料前逐项核对品质、来源、占用与替换代价，不将未知当成符合；战法支援锦囊增加紫色位，不能与重随条件混淆。

用户明确偏好：演武任务默认不执行git commit或git push，只有用户主动明确要求时才执行对应操作；本地提交授权不等于推送授权。修改前使用项目内notes/backups保护相关既有文件，不撤销历史提交。

必须明确账号及期次。用户只说“本期”时，读取该账号期次索引提出具体期次并确认，不跨账号或自动复用上期仓库。

```powershell
python scripts/event.py --user bixianjue --event s2-2026-09-02
```

只读取该期 `event.json` 和与本次问题有关的记录；需要支援核对时才读取该账号常规库存。公共规则按平台、赛季和本期截图核对。

每期保存原生仓库、逐轮选卡、支援、方案、战报和证据。新阶段留在同一期。用 `status` 区分建议、已确认和已撤回，未知不得默认确认；历史文件保持可追溯。

新建一期使用 `赛季-首次记录日期`，实际开赛日期未知时留空。不得从文件日期推算开赛时间。演武资源不能反写常规库存。
