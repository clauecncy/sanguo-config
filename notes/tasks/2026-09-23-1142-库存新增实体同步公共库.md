# 库存新增实体同步公共库

## 1. 原始需求

用户要求：个人库存更新时，若公共库缺少新武将或战法，应同步更新公共库，而非保留无实体 ID 的待补录项；公共库可能随赛季变化而不完整。

## 2. 我的理解

这是后续所有账号库存更新的规则，不是本轮提供了新库存清单。未知名称先核对图片与用户确认；确为新实体则先补公共定义和来源，再更新个人库存。

## 3. 执行步骤

检查现有库存更新、公共数据重建和证据规则；修改缺项处理、测试与工作流；运行测试并本地提交。

## 4. 涉及的业务逻辑

公共实体身份与个人拥有状态分离。图片只证明明确展示的字段，不自动认证未显示的赛季、完整效果或其他属性。

## 5. 修改前状态

`prepare_update` 查不到公共名称时写入 `entity_id: null`，`validate` 报告待补录，但仍允许库存更新完成。

## 6. 关键决策

新增缺项改为拒绝写入。公共数据由证据核准流程先补入 SQLite、SQL 基线和来源索引，独立重建通过后再重试库存更新；身份不清则向用户核对，不自动创造实体。

## 7. 具体修改点

`scripts/project_data.py` 在新条目公共定义缺失时抛错；`tests/test_project_data.py` 验证武将和战法均不产生无 ID 库存，并适配此前删除英雄张梁后的真实测试数据；更新库存、公共数据工作流及业务逻辑入口。

## 8. 验证结果

`python -m unittest discover -s tests -p test_project_data.py`：28 项通过。未改任何账号库存或公共数据库。
